# 1.07.01.02 Channel Sounder Developer Information

## Channel Sounder Test Pipeline
The channel sounder test pipeline consists of the following main steps:
1. Test execution using `channelSounder.py`
    * Transmitters and receivers are controlled via SSH commands to the M-VMs on each node.
    * Test logs are sent to Elasticsearch via Kafka.
    * Logstash ingests logs from Kafka and indexes them in Elasticsearch.
      * This pipeline is defined by `/home/elk/logstash/config/pipelines.d/channel_sounder_kafka.config` in the `ap_monitoring` container on `aerpaw-ops-server`.
2. Data fetched from Elasticsearch using `import_data.py`
3. Test data checked against baseline using `check_baseline.py`
      * The baseline is computed from historical data using `compute_baseline_from_es.py` and stored as a CSV file. The test data is compared against the baseline to identify any significant deviations in power or quality metrics.
4. Plots generated using `plot_results.py`
5. Email sent using `send_email.py`

Steps 2-5 are automated in `postTestTasks.sh`, which is run daily after the test cronjob.

Simply put, the data goes M-VMs -> Kafka -> Logstash -> Elasticsearch -> `import_data.py` -> `check_baseline.py` -> `plot_results.py` -> `send_email.py`

## M-VM Setup

There is a E-VM on each node that runs the channel sounder scripts and controls the USRP radios. To set up an E-VM for this test, run the following commands on each E-VM:

**Note**: The Channel Sounder E-VMs do not require any different images than the normal E-VMs. Any E-VM can be used to run the channel sounder test as all the relevant files are contained within the `AERPAW-Dev` repository. The scripts do however expect the E-VMs to follow this naming scheme: `M-VM-<node_id>` (e.g. `M-VM-LW1`, `M-VM-CC3`).

### To Set Up M-VM:

1. Rename E-VM: `sudo docker rename <E_VM_CONTAINER_NAME> M-VM-<node_id>`
2. Run command: `sudo docker update --restart unless-stopped M-VM-<node_id>`
    * This ensures that the M-VM will automatically start on boot.
3. Enter the terminal in the M-VM for each node (`sudo docker exec -it M-VM-<node_id> bash`)
4. Run command: `ln -s ~/AERPAW-Dev/AHN/M-VM/channel_sounder/startexperiment*.sh ~/`

## Radio Scripts
The channel sounder test runs the `startExperimentTX.sh` and `startExperimentRX.sh` scripts on each node to control the USRP radios for transmission and reception. These scripts are located in the `channel_sounder` directory and themselves call helper scripts that ultimately execute the `CSwSNRTX.py` and `CSwSNRRX.py` GRC scripts in the `$PROFILE_DIR/SDR_control/Channel_Sounderv4/` directory to control the USRPs.

Script Execution: `startExperimentTX.sh` -> `$PROFILE_DIR/ProfileScripts/Radio/Samples/startGNURadio-ChannelSounder-TX_v3.sh` -> `$PROFILE_DIR/ProfileScripts/Radio/Helpers/startchannelsounderTXGRC_v3.sh` -> `$PROFILE_DIR/SDR_control/Channel_Sounderv4/CSwSNRTX.py`
* `$PROFILE_DIR=AERPAW-Dev/AHN/E-VM/Profile_software"`

## GRC Scripts
The `CSwSNRTX.py` and `CSwSNRRX.py` scripts are GNU Radio Companion (GRC) scripts that control the USRP radios for transmission and reception. They take the following parameters:
- `--freq`: The frequency to use for the test (e.g. 3.5G, 915M)
- `--channel`: The channel number to use for the test (e.g. 0, 1)
- `--gaintx`/`--gainrx`: The gain to use for transmission/reception (e.g. 30)
- `--args`: Additional arguments for the script
  - This is commonly used to specify the serial number of the USRP to use for the test (e.g. `--args="serial=31EAC18"`)

The `.grc` files for these scripts that were used to generate the Python scripts are located in the same folder and are named `CSwSNRTX_wChannel.grc` and `CSwSNRRX_wChannel.grc`. These can be opened in GNU Radio Companion to view the flowgraph and make modifications if necessary.

**IMPORTANT**: There is a bug/issue in GRC that does not allow variables to be used in specifying the channel for a USRP source/sink. For this reason, the GRC flowchart uses a hardcoded value for the channel. If you make modifications to the `.grc` files, you must manually change the generated .py files to use the channel command-line argument instead. For example, in `CSwSNRTX.py`, you would need to change the following lines:
```python
# This would say usrp_source if it were the RX script
  self.uhd_usrp_sink_0 = uhd.usrp_sink(
      ",".join(("", args)),
      uhd.stream_args(
          cpu_format="fc32",
          args='',
          ### Line generated by GRC:
          channels=[0],
          ###
          ### Replace it with this line:
          channels=[channel],
          ###
      ),
      '',
  )
```
